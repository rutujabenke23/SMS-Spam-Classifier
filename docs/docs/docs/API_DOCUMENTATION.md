# API Documentation — SMS Spam Classifier

## Overview

The application is planned to use a Flask backend to connect the web interface with the trained machine learning model.

The following endpoints describe the intended API design. They must be verified against the implemented application.

## 1. Health Check

**Method:** GET

**Endpoint:** `/api/health`

**Purpose:** Check whether the backend is running and whether the trained model is loaded.

Example response:

```json
{
  "status": "ok",
  "model_loaded": true
}
```

The response fields may be adjusted to match the implementation.

## 2. Predict SMS Category

**Method:** POST

**Endpoint:** `/api/predict`

**Purpose:** Classify a submitted SMS message as SPAM or HAM.

Example request:

```json
{
  "message": "Congratulations! Claim your prize now."
}
```

Example response structure:

```json
{
  "success": true,
  "prediction": "spam",
  "probability": 0.92,
  "explanation": "The model classified this message as spam."
}
```

**Note:** The prediction and probability above are illustrative examples, not actual model results. The application must return values generated by the trained model.

## 3. Model Metrics

**Method:** GET

**Endpoint:** `/api/metrics`

**Purpose:** Retrieve evaluation metrics calculated from the model's held-out test set.

The response is expected to contain:
- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix

All reported metrics must come from actual model evaluation.

## 4. Input Validation

The backend should:
- Reject missing or empty messages.
- Validate incoming JSON.
- Enforce a reasonable maximum message length.
- Return appropriate HTTP status codes.
- Handle missing model files and inference errors gracefully.

## 5. Privacy and Security

- Do not send SMS messages to external classification services.
- Do not log complete user messages unnecessarily.
- Do not store submitted messages permanently.
- Render user-provided text safely in the frontend.
- Never treat a HAM prediction as proof that a message is safe.

## 6. Local Development

The planned local server address is:

`http://127.0.0.1:5000`

The actual address and endpoint behavior must be confirmed after the Flask application is implemented and started.
